# Moving from SQLite to Postgres

memracer runs on one database seam (`src/db.ts`): better-sqlite3 by default,
node-postgres when `DATABASE_URL` is set. The schema, queue semantics, and test
suite are identical on both. CI runs the full suite per backend
(`MEMRACER_TEST_DB=postgres` runs it over PGlite, real Postgres compiled to
WASM, through the same `PostgresDb` driver production uses).

## What differs per backend

| Concern | SQLite | Postgres |
|---|---|---|
| Selection | `MEMRACER_DB_PATH` (default `memracer.db`) | `DATABASE_URL` set |
| Ids | rowid `AUTOINCREMENT` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` |
| Integers | `INTEGER` | `BIGINT` (`Date.now()` overflows int4); int8 parses to JS number |
| Placeholders | `?` | `?` rewritten to `$n` by the driver |
| Legacy migrations | CHECK-widening rebuilds + `ensureColumns` on boot | none; no pre-seam Postgres databases exist |
| Backup | file-level replication of the SQLite file (Litestream or similar) | your provider's PITR/backups |

## Steps

1. **Provision** a Postgres 15+ instance. Create an empty database and note
   its `DATABASE_URL`.
2. **Quiesce**: stop the memracer server. The SQLite file is the source of
   truth the moment the process exits; WAL is checkpointed by better-sqlite3
   on clean close.
3. **Copy**:

   ```bash
   DATABASE_URL=postgres://... pnpm exec tsx scripts/migrate-to-postgres.ts /path/to/memracer.db
   ```

   The script creates the schema if missing, refuses a non-empty target,
   copies every table in FK-safe order inside one transaction (the circular
   `tasks.root_thread_id` FK is `DEFERRABLE` and checked at commit),
   preserves ids verbatim, advances each identity sequence past the copied
   maximum, and exits non-zero on any row-count mismatch.
4. **Verify** beyond counts (optional but cheap):

   ```sql
   SELECT state, COUNT(*) FROM tasks GROUP BY state;
   SELECT MAX(id) FROM tasks;   -- next submit must mint MAX+1
   ```
5. **Cut over**: start the server with `DATABASE_URL` set (and without
   `MEMRACER_DB_PATH`). Clients keep the same hostname.
6. **Fall back** (if needed): unset `DATABASE_URL` and restart. The SQLite
   file is untouched by the migration. Re-running the script later refuses a
   non-empty target; drop and recreate the Postgres database to retry.

## Testing against Postgres

- `MEMRACER_TEST_DB=postgres pnpm test` runs the full suite over PGlite; no
  server needed. This is what CI runs.
- `MEMRACER_TEST_PG_URL=postgres://... pnpm exec vitest run tests/db-driver.test.ts`
  additionally runs the driver-contract suite against a real Postgres through
  the production `pg` pool adapter. Use a disposable database: the suite drops
  and recreates the `public` schema per test.
- SQLite-specific tests (WAL backup, CHECK-widening migration rebuilds, file
  databases) stay pinned to the sqlite driver and run in both modes.
